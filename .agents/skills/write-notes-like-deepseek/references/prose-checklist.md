# 需要时读：笔记的行文与去掉过程痕迹

> 整理自 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 仓库里 `dsh-prose-standard` 与 `dsh-trim-cot-leakage` 两个 skill 中可以通用的部分。写或改笔记时对照；只改代码、不动笔记时不用读。

## 原则

- 只写代码说明不了的：行为、失败、先后顺序、谁负责、后果与取舍。不要复述代码，也不要写推导过程。
- 能写进类型、可见性或 API 报错的约束，不要只写在笔记里。
- 用平实的话写清楚谁做了什么、在什么条件下、结果是什么；少用“契约”“边界”“形态”这类抽象词，除非指的就是那个技术概念。不用口号、比喻和夸张的说法。
- 一件事只在一处讲清楚，其他地方链接过去；不要把同一条规则抄到很多地方。
- 写完问自己：不看实现，这段话能独立成立吗？不看当时的聊天记录，现在的读者能核对吗？

## 写之前的自查（来自 prose-standard）

- 每段话要完整：谁或什么做了什么、在什么条件或顺序下、是 must／may／never、有什么例外和“绝不”的保证、谁负责、有什么副作用、失败会怎样——缺一项就说不清。
- `implemented` 用现在时描述已经实现的事实；去掉计划的口吻和待办清单。
- 保留可以搜索的机制名，以及关键的 must／may／never、先后顺序与否定说法；少用装饰性的加粗和感叹。
- 刚学到一条规则时，把这次改动里类似的段落一起改掉，不要只改一处。

## 按章节检查

- **Decision／Consequences**：怎么区分、什么时候报错或拒绝、副作用、谁负责、先后顺序、取消、是否持久化，都写清楚了吗。
- **自由章节**（依赖关系、接口约定、数据结构）：写清各自的职责、依赖，以及不明显的选择和原因。
- **Alternatives／Consequences**：代价和收益都写，写明放弃了什么能力、什么条件下会重新引入。
- **Testing／Verification**：只解释“为什么这样验证”（为什么需要这个 fixture、这个断言、真实的入口），不要逐步复述测试过程。

## 去掉过程痕迹（来自 trim-cot-leakage）

对每段可疑的文字问：**这段话是不是只有看过当时的对话、PR 或草稿的人才看得懂？只看当前主干的读者能自己核对吗？** 不能的话，改成从仓库现状出发的写法，删掉对话的痕迹。能核对也不代表没问题——在 README、文档这类描述现状的地方，“以前怎样、现在改成怎样”的写法仍然属于下面第 3 类，要改掉。

常见的过程痕迹（发现就改）：

1. 没有出处的引用：`（决定 7）`、`（审计 C2）`、`§N`、`计划 §1.4` —— 改成引用已经提交的笔记或文档的具体路径；找不到出处的删掉引用，直接写事实。
2. 从 PR 或提交的角度写：`后续 PR`、`本 PR 新增`、`上一个 commit` —— 改成已经实现的机制或扩展点；没做完的用 `TODO` 或 issue 引用，或者放进 `## Deferred` 小节。
3. 写变化过程：`以前`、`不再`、`旧的 X`、`这次改动`、`现在` —— 改成现在时；要说明某个保护为什么存在，用现在时的假设句“如果没有 X，就会 Y”。
4. 写评审过程：`评审时否掉了`、`reviewer 确认`、`第 5 版` —— 只留决定和理由，删掉谁说的、什么时候说的。
5. 自己证明自己正确：`这样转换是安全的，因为……` —— 改成写出保证安全的不变式，或者直接删掉（代码已经说明了）。
6. 复述过程：`先做 X 再做 Y`、逐步讲解测试 —— 删掉，只留不明显的约定。
7. 含糊和占位：`应该够了`、`probably fine` —— 改成 `TODO`／`FIXME`，或者写出明确的边界。
8. 中英混杂：工作时随手写的中英混杂片段 —— 翻译或删掉。

**这些不算过程痕迹，保留：** issue 引用 `#1470`、`TODO(name):`（单独的 `TODO` 会被正文检查扫到，注意上一条的例外）、笔记与复盘里引用的已合并 PR、为什么关掉某个警告的说明、现在时的假设句、附实测数值的边界、运行时的新旧状态、已提交文档的 `§` 编号。

## 不要删过头（来自 trim-cot-leakage）

删之前，先把这段话里的每个论断列出来，再对照下面四种删过头的情况：

- 把“必须”“禁止”删成“可以这样做”——约束变成了可选项。
- 把“计划中”“考虑过”的假设删成已经实现的事实——proposed 被当成了 implemented。
- 只因为读起来像过程描述，就删掉一句真实的事实。
- 删掉支撑结论的出处：`实测：512 层嵌套约 0.15 s` 里的“实测”、出处与编号删掉，结论就没有依据了。
